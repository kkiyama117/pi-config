# 07 — Reality Check (software factories & business value)

The caveat layer: agents pass tests fast but codebases can still degrade —
architecture, boundaries and long-term maintainability still need humans at key
nodes. Realistic efficiency is 2–3×, not 10–100×, and business value should
come before methodology.

> 最近被 Harness Engineering、Loop Engineering 和「无人软件工厂」刷屏的人，建议认真看看这篇《Why Software Factories Fail》。
>
> 作者真正跑过几个月的全自动软件工厂，最后发现一个现实的问题：Agent 可以很快写出通过测试的代码，却未必能让代码库长期保持好改、好读、好维护。
>
> 测试几秒就能给出通过或失败，坏架构的账却可能几个月后才来。更多审查 Agent 和更多 Token 能抓住一些低级错误，但程序设计、边界划分、架构取舍和长期维护，目前仍然需要人来判断。
>
> 文章最后给出的路线很值得实践：先把产品目标、系统架构、函数和类型设计讲清楚，再把任务拆成可以逐步运行、逐步验收的纵向切片。小任务直接交给 Agent，大任务保持人类在关键节点里。
>
> 它没有鼓吹 10 倍、100 倍的全自动速度，而是接受当前模型的边界，安全地获得 2—3 倍效率。
>
> 这可能比继续堆 Skills、Prompt 和循环，更接近 AI 编程真正成熟的样子。
>
